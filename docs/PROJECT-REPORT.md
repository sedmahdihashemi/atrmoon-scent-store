# گزارش پروژه عطرمون (atrmoon.top)

تاریخ: 2026-09-19
هدف این فایل: مرجعی ساده برای اینکه هر وقت لازم شد (الان یا بعداً) بدانیم سایت از چه قطعات ساخته شده و هر قطعه کجا وابسته به Lovable است.

## ۱. سایت از چه چیزهایی ساخته شده

سایت یک اپلیکیشن وب است که با فریم‌ورک TanStack Start ساخته شده (یک تکنولوژی مشابه Next.js). این یعنی سایت هم صفحات را نشان می‌دهد و هم چند "API" کوچک دارد (مثل صفحه‌ی ورود، سبد خرید، پنل ادمین/فروشنده، و webhook ربات بله).

سایت برای اجرا به یک برنامه‌ی Node.js نیاز دارد (نه فقط چند فایل HTML ساده)، چون بخش‌های سرور (مثل ورود کاربر، ثبت سفارش، ارسال پیام به بله) باید روی یک سرور در حال اجرا پردازش شوند.

## ۲. دیتابیس و لاگین (Supabase / Lovable Cloud)

- تمام اطلاعات سایت (محصولات، سفارش‌ها، کاربران، فروشگاه‌ها، نظرات) در یک دیتابیس Supabase ذخیره شده که Lovable آن را برای پروژه‌ی شما ساخته و مدیریت می‌کند (آدرس: `gxoignprlnlwindigjkx.supabase.co`).
- این دیتابیس **مستقل از جایی که سایت را اجرا می‌کنیم نیست** — یعنی حتی وقتی سایت را روی هاست خودتان اجرا کنید، اطلاعات همچنان روی سرور Lovable Cloud/Supabase ذخیره می‌شود، مگر اینکه جدا آن را هم منتقل کنیم.
- به همین دلیل اگر آن آدرس Supabase از ایران فیلتر باشد، فقط انتقال سایت به هاست خودتان کافی نیست — باید یا یک پروکسی بگذاریم (که همین کار را فایل `Caddyfile` با مسیر `/sb` انجام می‌دهد) یا دیتابیس را هم واقعاً جابه‌جا کنیم.
- **قدم ۱ راهنمای SELF-HOSTING.md دقیقاً همین را تست می‌کند**: آیا از هاست شما اصلاً می‌شود به این آدرس Supabase وصل شد یا نه. این تست هنوز انجام نشده.

## ۳. چه چیزهایی از قبل برای خروج از Lovable آماده شده

Lovable قبل از تمام شدن اعتبار شما این فایل‌ها را اضافه کرده بود:

- **Dockerfile**: دستور ساخت (build) و اجرای سایت با Docker، خروجی یک سرور Node.js معمولی است.
- **docker-compose.yml**: اجرای همزمان دو سرویس: سایت (app) و یک پروکسی به اسم Caddy.
- **Caddyfile**: تنظیم Caddy برای دو کار — گرفتن گواهی SSL رایگان و رایگان برای دامنه، و پروکسی‌کردن مسیر `/sb/*` به سمت آدرس Supabase (تا مرورگر کاربر مستقیم با Supabase حرف نزند، فقط با دامنه‌ی خودتان).
- **docs/SELF-HOSTING.md**: راهنمای قدم‌به‌قدم اجرا با Docker Compose.

نکته‌ی مهم: همه‌ی این‌ها فرض کرده‌اند که هاست شما **Docker** دارد. طبق چیزی که گفتید، پنل شما DirectAdmin روی یک هاست اشتراکی است که معمولاً Docker ندارد. پس این مسیر (Docker) احتمالاً مستقیم روی هاست شما قابل استفاده نیست، مگر با VPS. این را در مرحله‌ی بعد با شما بررسی می‌کنم.

## ۴. متغیرهای محیطی (Environment Variables)

این‌ها مقادیری هستند که سایت برای اجرا لازم دارد و نباید داخل کد نوشته شوند، بلکه در تنظیمات سرور/هاست قرار می‌گیرند. الان در فایل `.env` (که در گیت commit نمی‌شود چون در `.gitignore` نیست — نکته: `.env` الان در gitignore نیست، باید مراقب باشیم آن را commit نکنیم) این مقادیر هست:

| متغیر | برای چی استفاده می‌شود |
|---|---|
| `VITE_SUPABASE_URL` / `SUPABASE_URL` | آدرس دیتابیس Supabase |
| `VITE_SUPABASE_PUBLISHABLE_KEY` / `SUPABASE_PUBLISHABLE_KEY` | کلید عمومی (anon) برای اتصال به دیتابیس — این کلید برای نمایش در مرورگر مشکلی ندارد |

این دو متغیر دیگر **در `.env` فعلی نیستند** ولی کد به آن‌ها نیاز دارد:

| متغیر | برای چی | وضعیت |
|---|---|---|
| `SUPABASE_SERVICE_ROLE_KEY` | کلید مدیریتی دیتابیس (دور زدن قوانین امنیتی RLS) — لازم برای پنل ادمین سمت سرور و **همه‌ی دستورات ربات بله** | فقط داخل Lovable Cloud در دسترس است؛ من در کد بررسی کردم و این کلید فقط برای «اطلاع‌رسانی سفارش» لازم نیست — تقریباً **کل ربات بله** (ورود با ایمیل/رمز، `/orders`، `/track`، `/review`) از این کلید استفاده می‌کند. یعنی توضیح فایل SELF-HOSTING.md که می‌گوید «خود ربات کار می‌کند» را باید با احتیاط در نظر بگیریم — بدون این کلید به‌احتمال زیاد ربات اصلاً کار نمی‌کند، نه فقط اطلاع‌رسانی سفارش. باید تست شود. |
| `BALE_BOT_TOKEN` | توکن ربات بله شما برای ارسال پیام | باید شما آن را از @BotFather بله دارید و در سرور جدید تنظیم کنید |
| `LOVABLE_API_KEY` / `LOVABLE_SEND_URL` | ارسال ایمیل — این سرویس، سرویس اختصاصی Lovable است (نه یک سرویس ایمیل عمومی مثل SendGrid)، پس صف ایمیل بدون اتصال به Lovable اصلاً کار نمی‌کند، حتی اگر کلید سرویس دیتابیس را هم داشته باشیم | نیاز به تصمیم: یا از Lovable جدا نشویم برای این بخش، یا سیستم ایمیل را با یک سرویس دیگر (مثل ایمیل خود هاست یا یک سرویس ارزان مثل Resend/Mailgun) جایگزین کنیم |

## ۵. ربات بله (Bale)

- Webhook ربات در مسیر `/api/public/bale/webhook` پیاده‌سازی شده (فایل `src/routes/api/public/bale/webhook.ts`).
- امکاناتش: ورود با ایمیل/رمز حساب سایت، دیدن آخرین سفارش‌ها، پیگیری سفارش با کد رهگیری، ثبت نظر برای محصول، و اطلاع‌رسانی خودکار سفارش جدید.
- همان‌طور که در بخش ۴ گفتم، تقریباً همه‌ی این امکانات به `SUPABASE_SERVICE_ROLE_KEY` نیاز دارند، نه فقط اطلاع‌رسانی سفارش.
- بعد از هر جابه‌جایی دامنه، باید آدرس webhook با یک درخواست ساده (که در SELF-HOSTING.md هست) به بله معرفی شود.

## ۶. چطور سایت روی سرورهای مختلف build می‌شود

فایل `vite.config.ts` طوری نوشته شده که بسته به محیط، خروجی متفاوت می‌سازد:

- پیش‌فرض: خروجی برای Cloudflare (سرویس ابری Lovable قبلاً از این استفاده می‌کرد).
- اگر متغیر محیطی `VERCEL` ست باشد: خروجی مخصوص Vercel (فایل `vercel.json` هم برای همین هست؛ به‌نظر می‌رسد یک بار امتحان Vercel هم بوده).
- اگر متغیر محیطی `SELF_HOST=1` ست باشد: خروجی یک سرور Node.js ساده (`node-server`) — همین حالتی که `Dockerfile` استفاده می‌کند و برای هاست شخصی مناسب است.

## ۷. جمع‌بندی وابستگی‌ها به Lovable

| بخش | وابسته به Lovable هست؟ | توضیح |
|---|---|---|
| نمایش سایت (صفحات، عکس‌ها، طراحی) | خیر، بعد از build مستقل است | با `SELF_HOST=1` قابل اجرا روی هر Node.js |
| دیتابیس و لاگین کاربران | بله، فعلاً | روی زیرساخت Supabase که Lovable مدیریت می‌کند |
| اطلاع‌رسانی سفارش در ربات بله + بقیه‌ی دستورات ربات | بله | نیاز به `SUPABASE_SERVICE_ROLE_KEY` که فقط در Lovable Cloud هست |
| ارسال ایمیل (صف ایمیل) | بله، کامل | از سرویس اختصاصی ایمیل Lovable استفاده می‌کند |
| اجرای سایت با Docker | نیازمند Docker روی هاست | هاست اشتراکی معمولی DirectAdmin معمولاً Docker ندارد |

## ۸. قدم بعدی

قبل از هر اقدامی باید از شما این‌ها را بپرسم چون از روی کد قابل تشخیص نیست:
1. آیا در پنل هاست شما گزینه‌ای برای اجرای Node.js (مثل «Node.js Selector» یا «Setup Node.js App») هست؟
2. آیا SSH یا Docker روی هاست‌تان در دسترس است؟
3. سرور هاست شما داخل ایران است یا خارج؟
4. مدیریت DNS دامنه `atrmoon.top` الان کجاست (همین پنل DirectAdmin، یا جای دیگری مثل ثبت‌کننده‌ی دامنه)؟

بر اساس جواب‌ها، یکی از این مسیرها را پیشنهاد می‌دهم: (الف) اجرای Node روی همین هاست، (ب) تبدیل بخش‌های ممکن سایت به نسخه‌ی استاتیک ساده، یا (ج) یک VPS ارزان ایرانی برای اجرای Docker.
